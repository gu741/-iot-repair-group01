# 需求说明

## 角色与范围
报修人：查看设备信息，选择清单内设备并提交非空故障描述，生成工单。
维护人员：查看设备信息，对工单执行“开始维修”和“完成维修”，更新工单状态。
范围：只分析查看设备、提交报修、更新工单状态三项功能；不实现网页、数据库、登录、真实物联网通信。

## FR-01 查看设备信息
角色：报修人、维护人员。
前提：设备已列入模拟设备清单 data/devices.csv。
行为与正常结果：按设备编号查询，显示设备编号、名称和位置；指定编号存在时返回对应设备信息。
异常结果：指定编号不存在时给出“设备不存在”提示，不返回其他设备信息。
验收方法：查询 DEV-001，应显示“温湿度传感器 / A101教室”；查询不存在的 DEV-999，应提示设备不存在。

## FR-02 提交报修
角色：报修人。
前提与输入：设备已列入清单；报修人选择清单内设备，填写非空故障描述。
正常结果：生成一张工单，记录 deviceId 和故障描述，工单初始状态为 PENDING。
异常结果：未选择设备或故障描述为空时提示补充，不创建工单。
验收方法：对 DEV-001 提交“传感器没有读数”，检查工单 deviceId=DEV-001、描述正确、初始状态为 PENDING；提交空描述时不生成工单。

## FR-03 更新工单状态
角色：维护人员。
允许的转换：PENDING → PROCESSING（开始维修）；PROCESSING → COMPLETED（完成维修）。
拒绝的转换：PENDING → COMPLETED（跳过处理中）；COMPLETED → PROCESSING（已完成回退）；同一状态转自己；其他所有组合。
正常与异常结果：允许转换时工单状态更新为目标状态；拒绝转换时状态保持不变并给出拒绝提示。
验收方法：对 PENDING 工单执行“开始维修”，状态变为 PROCESSING；对 PENDING 工单直接执行“完成维修”，应被拒绝且仍为 PENDING；对 COMPLETED 工单执行“开始维修”，应被拒绝。

## 已确认的实验规则
新工单为PENDING，仅允许PENDING转PROCESSING、PROCESSING转COMPLETED。
其他转换一律拒绝。本实验暂不实现完整报修系统，只实现状态判断函数。
